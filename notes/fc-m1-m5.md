TextView selection/copy dialog for exactly the displayed bounded page. The

## Provider formats

An optional `format` row in `transport.profile.tsv` selects `chat-completions`
(default) or `responses`. The four required rows remain origin, ca, model and
path. Format selection is explicit, never guessed from a URL. Authorization
remains a separate private runtime file. Requests contain a single user prompt;
multi-turn provider context and account authentication remain unfinished.

Responses requests use `input`, not `messages`. The decoder accepts usage-only
Chat Completions chunks without changing text or completing the request, and
retains reasoning-summary part/done and refusal-done events as bounded durable
events. Unknown/oversized events still fail. Event storage never executes tools.

The credential-free TLS fixture checks complete request structures for both
formats, all existing loss/failure/cancellation paths, usage and Responses
reasoning-summary events, fresh-process replay and exactly thirteen POSTs:
eleven scenarios and two explicit retry submissions. Unit cases check exact
UTF-8/escape bytes, capacity boundaries, malformed formats and empty-choice
rejection without a usage object. No live-provider success is inferred.
