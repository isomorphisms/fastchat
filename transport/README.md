# FastChat HTTP/3 transport experiment — MIRO A1

This independent branch adds a real native HTTP/3 transport and an executable Idriç adapter
under `model_request → transport → model_event`. It targets MIRO A1's
`armeabi-v7a` Bionic runtime. The core and renderer contain no connection,
socket, TLS, HTTP stream, pooling or QUIC identity. There is no application
renderer or APK in this experiment.

The exact independently fetched base is
`b49f0f7083d2d034ba76b910a43592d6d07bd18b`. The semantic reference is
[isomorphisms/fastchat PR #4, “Implement executable Idriç conversation core”](https://github.com/isomorphisms/fastchat/pull/4),
head `c66021957fb5dc195a995b2c0cd212863ff68915`. Its core and original tests
are copied unchanged into `examples/autogenerated/http-transport/` to allow
qualification without merging or depending on that branch. `HttpTransport.idric`
is a symlink there to the authoritative adapter in this directory.

## Boundaries

| Boundary | Implementation and responsibility |
| --- | --- |
| Conversation | Unmodified typed core owns request/attempt identity, canonical event admission, uncertain delivery and retry. |
| Transport adapter | `HttpTransport.idric` lowers checked identities and maps observations back to typed events. HTTP configuration and provider serialization are caller-supplied transport authority inputs. |
| Provider/event framing | `native/sse.c` feeds incremental bounded SSE records; `provider_framing.c` interprets the fixture's UTF-8 text and `[DONE]`. These files have no HTTP/TLS/socket dependency and are tested without libcurl. Production provider JSON interpretation belongs here, rather than in an HTTP engine. |
| HTTP semantics and engine | `native/curl_transport.c` submits HTTPS POSTs, owns two private request channels and bounded rings. libcurl, nghttp3 and ngtcp2 implement HTTP3/QPACK/QUIC. H2 capability remains linked for an incremental size comparison. Requests selected as H3 use `3ONLY`. |
| Secure channel | Pinned OpenSSL TLS 1.3 handshake/keying through ngtcp2's maintained crypto adapter. Certificate and hostname verification are mandatory. No 0-RTT submission is enabled. |
| Network channel | UDP and QUIC packet protection/recovery/congestion/path state remain below HTTP; curl/ngtcp2 own them. No socket, connection ID, packet identity or migration state crosses the opaque transport ABI. |

The maintained library's secure/network boundaries are used rather than a new
TLS or HTTP state machine. This adapter is not a generic serial BIO for curl.
A delegated broker can replace the native HTTP driver and feed the same framing
functions, or return already framed events through the same typed Transport.
Neither option requires a conversation or renderer change. See
[the delegated-channel note](../notes/transport-delegated-channel.md).

## Ownership, limits and loss

One owner thread drives each opaque session. One authority/origin, one cached
connection and at most two active requests are allowed. Each request owns a
64 KiB request-body copy, 64 KiB raw receive ring, 16 KiB cumulative delivered
header budget, and bounded 4 KiB SSE line/record buffers. Each emitted record
is at most 4095 bytes. Embedded NUL, malformed UTF-8, oversized framing,
non-success status and unsupported response encoding are rejected. There is no
unbounded application event queue. Calls to `fc_next` release receive credit;
a stalled consumer invokes curl pause/resume. The pinned curl patch shrinks
protocol receive windows because an application ring alone does not bound
curl's paused-stream buffering. These are buffering limits, not a claim of
constant whole-process RSS or a complete hostile-header memory audit.

The transport preserves each request and attempt through its channel, never
deriving an identity from a wire stream. Cancellation addresses both and removes
only that easy handle. It does not mean the remote model stopped or that billing
was avoided. A peer reset, connection failure, timeout or HTTP EOF without the
provider's completion marker yields `FC_UNCERTAIN`, mapped to the core's
`response_connection_lost`. This conservative result does not infer acceptance
from upload counters. Malformed/oversized protocol or provider data yields a
failed result. A completion marker followed by connection loss remains completed.

The engine performs no application retry. A small audited curl patch disables
its internal request replay. The core explicitly creates a new attempt. After
loss the connection cache is discarded once old attached requests have drained;
the fixture checks exactly one new connection and no hidden POST. An old-attempt
chunk is submitted to the real core after retry and rejected without changing
its canonical log. The Idriç FFI currently checks identities fit positive signed
32-bit values; the core's distinct identity types remain unbounded.

## Reproduction

All builds run on a Linux build host, never on A1. Set `ICK` to the exact qualified
C driver from ICK `c61e448251744a2f40ad743ebef1a027bdcd2f9d` before invoking
the recipes; `ICK_FLAGS` may supply explicit resource paths for an uninstalled
driver. The pinned `isomorphisms/ai-ci` producer actions at
`015cc7901ae0b3ad262b476f24e129b53c56db95` build the host or ARM driver.
`OwnedC.mk` compiles maintained C to assembly with ICK, then uses the existing
NDK assembler and platform linker. The A1 profile remains ARMv7/API 24; foreign
library compilation and the existing Idriç/runtime gates retain their roles. Use the Grease recipes in
`_/transport/`; the prerequisite host compiler is Android NDK r29. CMake 4.4.4,
GNU make, Perl and Git build the pinned foreign libraries. Paths passed to these
recipes must be absolute. The scripts are Grease, not Bash.

1. `grease /ABS/fastchat/_/transport/fetch.grease /ABS/fastchat /ABS/sources 3`
   prepares exact sources and verifies the complete policy patch.
2. `grease /ABS/fastchat/_/transport/build.grease /ABS/fastchat /ABS/sources /ABS/build /ABS/android-ndk-r29 a1 3 /ABS/cmake`
   builds the ARMv7 DSO and standalone probe. Use `host` instead of `a1` for
   executable host qualification. `link.grease` repeats only the native glue link.
3. `qualify.grease` takes root, host output, evidence directory, protocol, Python
   executable (unused for H2), Idriç compiler, Idriç library path, Idriç support
   path, Chez executable and NDK root. It compiles the typed adapter/test, runs
   the standalone framing test, and qualifies the live fixture. Compiler exit
   status alone is insufficient: the pinned compiler can print errors with zero
   status. The harness checks diagnostics and actual test assertions.

`qualify.js` can also drive an already built probe: arguments are probe, `3`,
output directory, pinned Python executable, and optional compiled typed-core test.
Install the hash-pinned fixture wheels on the host and expose them with PYTHONPATH.
It creates an ephemeral trusted TLS certificate, starts aioquic's H3-only server,
and requires deterministic payloads, resets, closes and stream identities.
No production provider account or credentials are used. `FC_FIXTURE_PORT` selects
a test port. `FC_FIXTURE_DROP_EVERY=7` drops each seventh incoming datagram after
ALPN, and `FC_TEST_PATH_LOSS=1` additionally exercises `/blackhole`, dropping all
traffic on the old session. Loss still yields uncertainty and a fresh attempt.

For eventual A1 qualification, `serve.grease` takes repository root, certificate
directory, protocol, bind address, certificate SAN list, port and Python path.
It starts a controlled host fixture. Transfer only its public certificate and
the built archive to A1; never install a compiler there. A1 runs the standalone
probe against that host with the matching trusted certificate. The fixture host
needs TCP reachability for H2 and UDP for H3. Preserve device identity, kernel,
ABI, artifact digests and separate installation/launch/runtime receipts.

## Qualification limits

The native artifact is built for A1; its installation and execution are
**BLOCKED/NOT_RUN** because no physical A1 connection is available in this job.
The live Idriç adapter/core test uses the pinned compiler's host Chez backend.
It does not establish ARM/Thumb FFI or on-phone core execution. A native product
integration must still qualify that backend and polling FFI on A1.

Provider authentication, request JSON serialization, provider-specific response
JSON/tool events and production endpoint compatibility are **NOT_RUN**. The
included provider is intentionally a deterministic fixture text/SSE adapter.
No ChatGPT account support, OpenAI credentials, HTTP/3 production support,
Android lifecycle behavior or physical process/service inventory is inferred.
The resolver in this small build is synchronous; DNS can block its owner thread.
The 5 s establishment and 30 s whole-request deadlines are experiment policy,
not final product settings for long model responses.

The original reference test suite prints a retry assertion failure even though
its process exits zero (expected log size 10, observed 9). Its unchanged source
and result are retained. The added test independently verifies the intended
fresh-attempt, uncertain-delivery and stale-event invariants and passes.
